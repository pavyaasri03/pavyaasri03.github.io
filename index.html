Teachers turn study material into reviewed assessments; students take practice quizzes and exams, then inspect their results.

  • Teacher & student workflows. Built approve/edit/regenerate review tools, publish-by-type selection, an exam player with timer and question palette, and results analysis.

How the system fits together

Why I chose this approach
Keep correctness-critical scoring deterministic; use a bounded AI judge for descriptive answers. Source-grounded generation passes through verification, repair and teacher review before publishing.
A problem I debugged
A Pydantic response-model mismatch prevented quiz starts. I reproduced the failure and corrected the response contract; I also fixed a query path that assumed one result when several could exist.

02 / LANGUAGELINGOCUT

LingoCut

Multilingual dubbing.
Meaning, kept in sync.

An AI dubbing and script-to-voiceover application for educational content.

English lectures become colloquial, code-switched speech while the original video stays intact. Scripts can also become standalone voiceovers after an editable translation preview.

What I built

  • Two media workflows. Built video/audio dubbing and script-to-voiceover flows using React, Node.js, Gemini and FFmpeg.
  • Timing & job control. Implemented segment-based processing, pitch-preserved time fitting, retries, hard timeouts and checkpoint/resume for long jobs.
  • Speech reliability. Diagnosed dropped sentences, replaced a lossy splitter and checked text retention using TTS-to-transcription round trips.
12code-switched dialects
supported by the workflow
  1. Transcribe
  2. Translate
  3. Fit speech
How I built it and what I learned +

How the system fits together

  1. React upload / editable preview
  2. Express background job + task polling
  3. Segment → Gemini Live / TTS
  4. FFmpeg time-fit → mux / WAV download
Why I chose this approach
Separate faithful transcription from colloquial translation so domain terms can stay precise. Fit each generated speech segment into its original time slot without shifting pitch.
A problem I debugged
Quoted sentences disappeared before they reached TTS. Round-trip checks led me to the sentence-splitting regex, not the speech model. I replaced it with a parser that preserves trailing quotes and brackets.
How I checked it
Used text-retention checks and TTS-to-transcription round trips, including quoted dialogue and spoken digits. Per-segment retries and checkpoints support recovery when a long run is interrupted.
What to keep in mind
Splitting work into independent speech calls can introduce voice variation. A consistent voice directive and controlled chunk sizes help manage the seams; checkpoints preserve completed work.

MarketInsight Pro

Marketing signals.
Context for action.

A social-listening and SEO intelligence platform for an education brand.

Marketing teams need to distinguish relevant brand and competitor mentions, understand trends, and review replies grounded in the company’s actual offering.

What I built

  • Collection & analytics. Built multi-source social listening, sentiment and relevance tagging, competitor views and persistent daily rollups for trend analysis.
  • AI-assisted workflows. Integrated Groq, Gemini and Claude for classification, content research and fact-grounded reply drafts with human review.
  • SEO & API integration. Built search-performance panels, rank tracking and audit workflows; kept third-party secrets behind a server-side API proxy.

  1. Collect

How I built it and what I learned +

How the system fits together

  1. React UI + service / cache layer
  2. Vercel API proxy keeps provider keys
  3. Source APIs + task-specific LLMs
  4. Firestore daily rollups → trend charts
Why I chose this approach
Choose models by task, quota and cost. I moved classification from Gemini to Groq when the daily cap became a bottleneck, and exposed each source’s fetch outcome instead of silently treating failure as no mentions.
A problem I debugged
“CA” matched California as well as Chartered Accountancy. I added contextual disambiguation and an LLM relevance layer, and corrected brand attribution so competitor comparisons used the right mentions.
How I checked it
Per-source outcome reporting makes failed collection visible. Historical rollups retain daily sentiment and volume; grounded reply drafts remain subject to human review before use.
What to keep in mind
Collection completeness depends on third-party quotas and source availability. Retry/backoff and quota messages make those limits visible; grounding reduces unsupported claims but still needs review.

Smart Attendance

Academic operations.
Clear rules, usable tools.

A multi-tenant attendance and academic-tracking platform for institutions.

Faculty, students and administrators need consistent class schedules, reliable onboarding and role-specific views of attendance and coursework.

What I built

  • Faculty onboarding. Built self-onboarding and retroactive timetable assignment, including API routes, a database migration and the onboarding interface.
  • Scheduling. Built weekly timetables for faculty, students and super-admins, with multi-day slot creation and overlap detection.
  • Product reliability. Fixed a face-capture failure blocking registration, consolidated shared dashboard components and delivered responsive layouts.

How I built it and what I learned +

How the system fits together

  1. Next.js role-specific dashboards
  2. API routes + Zod validation
  3. Supabase Auth + PostgreSQL / RLS
  4. Timetable assignment + overlap checks
Why I chose this approach
Support class timetables before a faculty member is assigned. The schema migration allows that intermediate state; onboarding then connects the new faculty record to existing classes.
A problem I debugged
A face-capture failure blocked faculty onboarding. I fixed the capture/loading path and also resolved dashboard regressions during the shared-component rollout.
How I checked it
Overlap detection checks conflicting class slots. Strict TypeScript exposed status comparisons that could never match the API response; I corrected those guards and course-selector visibility bugs.
What to keep in mind
My scope was full-stack feature delivery across onboarding, scheduling and dashboards. Face verification and geofencing are platform capabilities, not claims that I trained a recognition model.
